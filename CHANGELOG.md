## [2.0.5] — 2026-02-24

### Cambio de modelo: Rule AUTOGENERADA

**Eliminado symlink y copia manual.** Ahora `.cursor/rules/prestashop.md` es un archivo generado:

```bash
<!-- AUTOGENERATED - DO NOT EDIT -->
<!-- Source: governance/prestashop/rules/prestashop-main-rule.md -->

[contenido del source]
```

**Por qué este cambio:**
- Elimina bug de `-type f` vs `-type l` (symlinks no se contaban)
- Comportamiento idéntico en Linux/macOS/Windows
- Verificación de sincronización más robusta
- Un solo flujo, sin casos especiales por OS

### Corregido

- **Defaults de repos** — Cambiados de `iagt/` a `inigo-munoz/` (workspace real)

### Añadido

- **Rollback transaccional en `update-governance.sh`**:
  - `PRE_UPDATE_SHA` guarda estado del repo antes de cualquier cambio
  - `git reset --hard` al SHA original si hay error
  - Garantiza que el repo nunca queda en estado intermedio

- **`verify-governance.sh --quiet`** — Modo silencioso para uso programático

- **`normalize_version()`** — Auto-añade prefijo `v` si el usuario escribe `2.1.1`

- **`version_file_needs_regeneration()`** en setup — Regenera VERSION_FILE si:
  - No existe
  - RULE_HASH no coincide con source actual
  - CORE_REPO o PRESTASHOP_REPO difieren del configurado

- **Verificación de indexabilidad en verify** — Comprueba:
  - Que `.cursor` existe
  - Que `.cursor/rules` no está en `.gitignore`

### Modificado

- **Los 3 scripts completamente reescritos** con el nuevo modelo:
  - `setup-governance.sh` — Genera rule activa, regeneración inteligente de VERSION_FILE
  - `update-governance.sh` — Regenera rule activa, rollback transaccional
  - `verify-governance.sh` — Comparación determinista con `tail -n +4` (sin heurísticas)

- **`check_rule_sync()` simplificado** — Elimina heurística, usa:
  ```bash
  tail -n +4 "$RULE_TARGET" | diff -q - "$RULE_SOURCE"
  ```

### Principios arquitectónicos

> La rule activa es un archivo GENERADO, no un symlink ni una copia manual.
> VERSION_FILE se regenera si detecta inconsistencias (hash, repos).
> Comparación determinista sin heurísticas frágiles.

## [2.0.4] — 2026-02-24

### Añadido

- **`verify-governance.sh --quiet`** — Modo silencioso para uso programático:
  - Solo retorna exit code (0=OK, 1=FAIL)
  - No imprime output
  - Permite usar verify como fuente de verdad en scripts

### Modificado

- **`setup-governance.sh`** — Detección de estado basada en verificación integral:
  - CASO 1: `verify --quiet` pasa → Instalación COMPLETA (usar update)
  - CASO 2: Subtrees con contenido real pero sin version file → Instalación PARCIAL
  - CASO 3: Nada existe → Instalación LIMPIA
  - Verifica contenido REAL de subtrees (`governance/core/framework/`, `governance/prestashop/rules/`)
  - No acepta carpetas vacías como subtrees válidos

### Principio arquitectónico

> `verify-governance.sh` es la única fuente de verdad para determinar estado de instalación.
> La existencia de archivos/carpetas no es suficiente para determinar instalación completa.
